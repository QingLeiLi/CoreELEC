# E900V21C UWE5621DS Wi-Fi / 蓝牙接入

2026-11-28。基于 `491fb30742`。状态：源码与镜像包接入完成，主机验证通过；完整 ARM 编译、部署、扫描/连接/配对待验。本轮未访问或改变盒子的网络、未重启。

## 依据与边界

- 板上标识 UWE5621DS。原机 `backup/1055E4A92BD1（旧）/doc/dmesg.txt` 记录 `chipid: 0x56630001`、MARLIN3E、`three_ant`、TCXO outside clock，WCN 固件下载成功。不能仅按外壳名称选 UWE5622 驱动。
- 原日志 Wi-Fi interrupt=241、power=240，结合厂商 GXL GPIO base155，分别是 GPIOX_7 / GPIOX_6，IRQ HIGH。
- 本地 `gxlx2_p291_1g.dts` 是已使用 Android 固件族的参考设备树，不冒称来自原备份。它与上述 Wi-Fi 引脚一致，BT reset=GPIOX_17，仅有 reset，没有 P212 的 GPIOX_18 host-wake。后者仍需 Linux 实测复位有效性。
- 直接复用 pinned CoreELEC `fc61125e…` 已有的 `projects/Amlogic-ce/packages/linux-drivers/amlogic/uwe5631-aml`。其名字虽为5631，包描述、Makefile实际是UWE5621 SDIO Wi-Fi/BT。
- 驱动源：<https://github.com/CoreELEC/uwe5631-aml>，精确提交 `c9621e32c743ed37bdb54a60f8aa8b329b4bb56f`，archive SHA256 `19764d9bf428fa480708a767c6bfc9ab755d2559f58e17fed0c3659aa8608b74`。本地已下载核对；未升级为另一内核分支的驱动。

## 本轮接入

1. `usb-build.options` 增加 `uwe5631-aml`，仍不启用全套无关 Wi-Fi 固件包。
2. 板 DTS 启用 **sd_emmc_a**（d0070000，SDIO），不是 sd_emmc_b；增加 function1 `sprd,unisoc-wifi`，满足 CE 原有 SDIO udev 自动加载条件。保留 P212 的 SDIO 总线参数，未自行超频。eMMC、SD 插槽仍禁用。
3. Wi-Fi供电 X6、IRQ X7/HIGH；BT reset X17。删除 Broadcom专用 `dhd_static_buf`、未核实的 P212 PWM 编程以及 X18 唤醒脚。参考设备树32k pinmux保留；未配置PWM时厂商wifi_dt会打印配置缺失提示，不能把它单独当作模块失败。是否需要额外时钟初始化须看实际枚举/下载证据。
4. Linux0047将 BT host-wake 变为可选：无引脚不申请 GPIO/IRQ0，映射/申请失败不注册 wake IRQ，suspend/resume不操作无效IRQ。保留 rfkill复位、输入设备与SDIO通信，不宣称支持蓝牙唤醒。
5. 安装脚本只修 pinned UWE 配方的绝对路径 `find`：`.e900-work` 会导致原过滤式把所有 .ko 跳过。改用包内相对搜索，缺少任一必需模块即失败；版本/SHA不变、拒绝未知配方。之后Linux变化也会清理UWE模块构建状态，工具链复用。

镜像应包含：

| 类型 | 内容 |
|---|---|
| 模块 | `uwe5621_bsp_sdio.ko`、`sprdwl_ng.ko`、`sprdbt_tty.ko` |
| 固件目录 | `/lib/firmware/unisoc`（通过CE kernel overlay） |
| 固件/配置 | `wcnmodem.bin`、`wifi_56630001_3ant.ini`、`bt_configure_pskey.ini`、`bt_configure_rf.ini` |
| 自动加载 | 原包 `80-unisoc_sdio.rules`，加载 Wi-Fi / BT tty / hci_uart |
| 蓝牙服务 | 原包 `sprd_sdio-firmware-aml.service`，`hciattach -s 1500000 /dev/ttyBT0 sprd` |
| BlueZ | CE原有 `bluez-40-Add-support-for-sprd-type-in-hciattach.patch`；默认BLUETOOTH_SUPPORT=yes |

蓝牙经 SDIO 上的虚拟 `/dev/ttyBT0`，不是连接主板物理UART。内核现有 CFG80211、AMLOGIC_WIFI、AMLOGIC_BT_DEVICE、HCIUART/H4 已满足配置依赖，BSP调用的 sdio_reinit / sdio_set_max_regs / Wi-Fi与BT复位接口均有导出。

首次启动保持有线网，先保存如下只读信息，再决定是否扫描/配对：

```sh
uname -a
lsmod | grep -E 'uwe|sprd|hci_uart'
dmesg | grep -Ei 'wifi|wcn|marlin|sprd|sdio|firmware|bluetooth'
ls -l /dev/ttyBT0 /lib/firmware/unisoc
connmanctl technologies
bluetoothctl list
systemctl status sprd_sdio-firmware-aml.service --no-pager
```
