# GXLX2运行时SR能力保护修复（0030）

问题：global_output关闭后，get_video_enabled为假，primary_render_frame即使没有新VPP配置也会重刷缩放设置。vpp_set_super_scaler_regs的SR0/SR1顶层、core0配置/尺寸及关闭写入没有统一检查硬件能力；0021仅修初始化sync访问。

0030只针对GXLX2：按sr_info.sr_support保护SR专属访问，保留共享VE输入尺寸、输出尺寸和路径处理。没有跳过整个PPS设置，也没有将CPU全局伪装为GXL。用硬件能力原值而不是被super_scaler开关过滤后的临时掩码，因此用户关闭超分时，实际存在的核心仍会收到正常关闭配置。

测试执行真正的上游/补丁后完整函数，对10个CPU、4种能力掩码、刷新开关、超分开关、7条路径、3种尺寸和两组读回值进行I/O序列对比。除GXLX2无能力核心的访问被移除外，其余操作和值/顺序一致；共享尺寸读写保留。GNU89/GNU99通过。ARM构建、实际黑屏是否改善仍待验证，不能将主机通过当作修好画面。

0031随后补白盒跟踪，不改变HDR策略：固定点边界记录增加pps_calls/sr_support/sr_refresh，以及CSC/HDR状态、flags、null帧计数、video_on/wait_on、实际post/legacy/fake分支计数。未开启边界采集时不累计诊断计数。CSC分支计数是本次启动中开启采集期间的累计值，应看同一次记录内的增量，不能要求首项为0。

G12数值判断在本机是否选到了不兼容硬件路径，仍需跟踪结果和寄存器映射证据；本补丁没有将所有G12判断改掉，也未继续清未知GEN3位。
