## 2. 实验要回答的唯一主问题

把原global_output转换拆成两个因素：

- **S：软件关闭副作用**，包括get_video_enabled变化引出的PPS重刷、fake-frame/颜色处理。
- **B：真实硬件混合位转换**，本例VPP_MISC的VD1 pre/post两位，掩码`0x4400`；基准实际值100054b0，普通关闭100010b0。

|编号|S|B|目的|实现状态|
|---|---:|---:|---|---|
|A0|0|0|证明观测开启时参考正常|已有正控；每新boot仍需新鲜参考帧|
|C0|1|1|默认刺激能触发故障|Build291已有完整短脉冲证据；新内核或环境改变时需重做|

## 4. 每轮共同启动流程

### 4.1 授权与新boot

向用户明确说明本轮将软件重启、首播和一次指定脉冲；按用户回复执行。无需用户看屏幕即可由已校准回采判断的部分可自动执行，物理HDMI结论只能来自真实反馈。

1. 保存旧boot、当前播放器/解码器、global/hold/GEN3/RDMA、输出模式和空间，写manifest。
2. 发送一次reboot，等待SSH恢复，核对boot_id确实变化。超过预定启动等待（建议180秒）仍未上线，停止并报告；不连续重启、不自动刷机救援。
3. 等待期间可以整理离线数据；不写超过60秒的单次阻塞等待，每60秒内给用户简短进度。
4. 初始化status=1时才按现有流程arm netconsole→主机收到本boot READY→release-video-init。status=2直接记录已经完成；status为其他值先调查，不重放初始化。

已存在的工具：设备`/storage/e900-build279/arm-netconsole.py`、`release-video-init.sh`，repo也有源码。主机接收器`e900-port/scripts/receive-netconsole.py`。当前6669端口可能已有接收器；复用并按boot/时间切分，不能重复绑定、杀掉无关进程。接收地址/MAC先核实，历史为192.168.31.36 / 88:66:5a:40:f7:46。

### 4.2 首播与回采参考

1. Kodi TCP JSON-RPC确实响应且无active player、内核`No vdec.`，设置音量0并验证返回；初始普通提交记录器在播放前arm，保存generation。
2. `Player.Open`调用一次，存回执；观察H264解码器出现、帧计数推进，冻结初始提交并保存。不能因为等12秒失败就盲目再发；先查Player状态、日志和是否已解码。首播已经开始则绝不第二次Open。
3. 确认实验参数默认，设置本轮所需的唯一隔离参数，并记录原值。保持输出1080p60hz、同一片源。
4. 每个boot最多启动一次VDIN服务。先检查`/storage/e900-capture/session.txt`和start-phase的boot，已有本boot会话就核实复用，不能再次运行start脚本。
5. `e900-start-capture.sh`会通过管理API开CLKB，只允许在故障前首次启动做这一步。此后前后采图都必须`NO_GATE=1`，不补开钟、不重启VDIN来“修好采集”。
6. 在输出不切换状态取得正常参考。新硬件/模式、字节顺序或回采代码变更时，先正控并由用户确认与电视一致。本次同Build291相同路由已有正控，可由当前两帧彩条与移动标记建立新会话参考；不能拿旧PNG充当当前参考。
7. 正常参考要求两帧有效包、时间戳和completion严格递增、8色条位置正确、移动标记造成RGB hash变化、持续解码。失败即停止，不触发脉冲。
8. 开始脉冲时片子至少还剩3分钟；时间不足就停止本轮，不能用循环播放制造首播。先准备好脚本，再让用户确认画面。

## 5. A1：软件关闭、保持硬件混合位

### 5.1 固定条件及操作

- 新boot、同一20分钟片、同一VDIN会话，音量0；GEN3实验=N、RDMA不变；无像素selector访问。
- 设置`/sys/module/amvideo/parameters/gxlx2_blend_hold`为3；global_output起始为1、disable_video=0。
- 只运行一次0.2秒global_output关/开。采集器等待观测到off后再持有0.2秒，因此实际off时间稍长，按原始时间/帧计数报告，不强称精确200ms。
- 使用现有mode2、准备表和前后回采；脚本会在触发前再次取得正常双帧参考。

命令在盒子root shell执行；`E900_RUN`与`E900_TOOLS`必须由准备步骤设置为本轮绝对路径，不照抄旧输出路径：

```sh
printf '3\n' > /sys/module/amvideo/parameters/gxlx2_blend_hold
cat /sys/module/amvideo/parameters/gxlx2_blend_hold
python3 "$E900_TOOLS/e900-register-transition.py" \
  --off-seconds 0.2 --with-submissions --with-loopback \
  --loopback-calibrated --exercise-global-output \
  --out "$E900_RUN/transition.json" \
  > "$E900_RUN/collector.stdout" 2> "$E900_RUN/collector.stderr"
```

上面是采集本体，不是完整包装。包装必须独立保存exit code并进入收尾，不因非零退出跳过证据。

### 5.2 A1有效性：缺一项就不得进入因果分支

1. mode=2、status=3、reason=0；全部用于硬件判断的行flags=1、guard=0，代次和boot一致，有明确before/off/restored窗口。
2. 参数hold=3仅作意图。真实`live & 0x4400`在前、中、后**每个已记录的phase0/phase1**均为0x4400；完整live与基准相同。若其他位改变须单独说明，不能称只隔离两个位。逐VSync采样不证明两个采样间没有短暂变化，报告这一时间分辨率限制。
3. global确实1→0→1，enabled软件变化存在；关闭期PPS/CSC副作用确实发生。使用计数增量和实际表，而非参数文字。与C0短轮比较关键调用/表形状，不要求异步帧调度造成的批次数完全一致。
4. 提交overflow=0，覆盖恢复后至少16个VSync的观测范围；batch/IRQ/取消/pending均保留。末尾一批pending可接受为冻结时边界，但关键隔离/恢复批不能未经说明就缺完成关联。
5. 两张before参考有效；after正常/黑的判定看实际PNG及原包，时间戳和completion推进。两个after frame都正常且标记变化才报告“本轮未复现”。两个after全黑才报告“回环双帧黑”。单张黑＋用户明确黑屏为“部分图像证据，物理黑屏”；由astra决定是否可用于分支，sol不得自己升级成完整通过。
6. 无真实Stop、帧释放、解码器重开、模式切换、VDIN重启/开钟、GEN3额外实验，且采集程序已退出/探针不再active。

### 5.3 结果与后续

|A1结果|只允许得出的结论|审计后下一项|
|---|---|---|
|真实混合位保持，仍黑|在本观测分辨率和条件下，两个混合位关/开不是黑屏必要条件|准备B1/P1窄隔离，先审代码|
|真实混合位保持，正常|混合物理转换或其与软件副作用的交互值得优先查|先独立boot复核一次；一致后准备A2|
|hold未生效、guards失效、正常参考无效|实验无效|修实验条件；不解释根因|
|提交溢出、关键批次缺失或采集超时|证据部分缺失，保留已有效部分|astra判定能否分支；不自行重试|
|开启回采本身使参考变黑|观察方法干扰基准|停止脉冲，审查回采影响|

本轮最多一次脉冲。即使结果正常，也不直接在同一boot追加下一组；黑态尤其不能当下一组起点。

## 7. 收尾与异常规则

1. 先保存原始结果，再记录global_output；本轮若确实由自己写成0且尚未恢复，按既有collector清理恢复1，保留失败信息。探针代次变化时不要停止别人的会话。
2. 在global_output已为1且自己的记录器冻结后，将本轮修改的hold恢复原值，记录清理前后读回。正常情况原值0；原值非默认时本轮应在前提检查停止，而非覆盖用户设置。
3. 不Stop视频，不停止/重启VDIN，不执行时钟恢复，不重播。视频自然结束时记录结束时刻；结束之后的图像不作故障态对照。
4. 回采15秒超时可能是脚本/文件系统延迟：保留stdout/stderr、最终文件是否存在、文件发布时间、完成元数据和已有IRQ证据。不得直接称“硬件采不到”。不自动再抓两帧；astra可另行批准无扰动补采。
5. SSH丢失先尝试只读连接和主机日志检查；无响应时暂停设备操作，请用户配合并等待回复。不得自动断电/刷固件。
6. 所有实验都有采集时长/行数上限，禁止无限printk、无限寄存器轮询和无限重试。

## 8. A1之后的条件实验：目前均未实现

这些段落是实现与审计规范，不是现成可运行开关。sol不能编造sysfs名称就执行。

### 8.1 B1 / P1：仅在A1有效且仍黑时

共同固定：以A1为对照，hold=3、0.2秒、同模式同片源；新内核先做一次**所有新增开关关闭的A1对照**确认故障仍在。每组新boot、有效新鲜参考。

|编号|只抑制的内容|必须证明|不允许宣称|
|---|---|---|---|
|B1|本诊断global-off关联的fake-frame HDR硬件配置|命中次数、被阻断的具体VD1/OSD/wrapper写组、PPS仍执行、混合实际保持|整个HDR模块错误或GXLX2一定不支持HDR2|
|P1|本诊断global-off引出的冗余PPS刷新|调用guard命中、66字重复流消失、HDR关闭配置仍执行、混合实际保持|PPS硬件整体不支持或系数数值错误|
|BP|同时抑制上两项，仅当B1和P1都有效且仍黑后由astra决定|两项真实生效，其他条件一致|两模块都各自有bug|

默认先B1，astra可根据A1实际提交顺序调整并记明依据。B1结果归档审计后才执行P1，不能一口气跑矩阵。

实现细节必须覆盖：

- 默认关闭、仅GXLX2/legacy/未压缩VD1/已持有有效帧/明确实验代次；真正Stop、掉电、帧释放、模式改变立即退出隔离。不能把CPU ID整体改成GXL。
- **P1必须覆盖恢复第一拍：**global恢复1时enabled可能仍0，`!get_video_enabled()`仍命中；如果此时又执行了相同PPS重刷，不能声称隔离完整。实验窗口应关联关闭代次至软件enabled恢复，限时，并保留真正new_vpp_setting/尺寸变化的必要配置。若发生必要配置变化则本轮不再可比，标无效。
- B1尽可能仅抑制末端硬件提交，保留原软件状态轨迹；若跳过函数同时改变状态更新，必须逐项列出，按复合干预解释，不能称纯硬件单变量。不得跳过全局amvecm、关整个HDR或改全局csc_en。
- B1不能只处理VD1而漏掉同次调用中的OSD/wrapper写入后仍声称完整；要明确实际覆盖组。首次隔离可覆盖这次事务，后续依据结果细分。
- 计数不能被其他IRQ日志预算耗尽；日志需记录触发代次、before/skip/after、caller/选择参数。所有新增观测有界，不能每VSync无限输出。
- 源码审计和有意义的主机测试覆盖正常首播、真实Stop、不合格guard、关闭与恢复首拍、默认关闭/其他CPU保持原行为。准备B1/P1公共guard和记录设施时一次补齐，避免每个计数遗漏再构建。

判断：只有某有效隔离使故障消失，才把对应事务提升为主线，并用至少两次独立boot复核，再细分其写组。两者都有效但都黑且BP也黑时，降低这些**被覆盖事务**作为必要条件的优先级，转D；不能据此排除整个HDR/PPS硬件。

### 8.2 A2：仅在A1有效且正常并复核后

在既有VSync混合提交点实现有界硬件两位脉冲，软件global/enabled始终正常，PPS/HDR关闭副作用不发生。保持原RDMA模式和其他混合位；不使用任意MMIO接口。真实关闭/无帧时立即撤销实验，由正常路径接管，不能为了实验强开图层。

**现有collector以global下降识别off窗口，不适用于A2。**必须增加独立硬件脉冲标记/代次/开始结束VSync和对应窗口解析；禁止为了复用collector伪造global=0，否则不再是S=0。实际位关闭与恢复必须读回，记录其他调用计数无关闭增量。

新内核先验证默认C0和A1行为未改变；A2只运行一次后归档：

- A2黑、A1正常：硬件混合转换自身足以触发；查恢复顺序/握手，再局部拆pre/post，不能立即写未知reset位。
- A2正常、A1正常而C0黑：两因素交互，查相对VSync与提交顺序；不要随机试延时。预先指定一个可审查的顺序变化和恢复判据。
- 默认C0不黑或A1改变：先审新增代码/环境影响，不把A2结果当可比较证据。

### 8.3 D：仅当提交缺口/实际读回矛盾支持时

只针对本轮实际涉及的共享地址，追普通manager、OSD独立RDMA和直接WRITE路径的caller/值/时间/逻辑基值来源。固定允许列表，禁止扫全部寄存器。先证明某地址存在覆盖、丢提交或冲突，再选择修复；已有i/k缺陷不能凭主机复现自动宣布为实机根因。

正常HDR基准缺失时，可在其实际初始化路径开始记录软件写意图，涵盖早于PlayMedia的初始化；普通提交记录器不覆盖直接写，必须明确覆盖边界。未知硬件地址不靠盲读补齐，不盲调probe SMC。

## 9. astra审计接口与验收门槛

sol每轮提交AUDIT.md，固定使用以下结构：

```text
实验编号 / run路径 / OS commit / tools commit / boot_id
授权与实际执行：是否重启、首次播放次数、脉冲次数、VDIN start次数
唯一变量、固定条件、偏离计划项
基准证据：两张原包/PNG、completion/timestamp/移动标记
生效证据：关键原始行索引、actual位、guard、计数和实际表
结果：前/中/后时间线、图像、用户原话（没有则写未观察）
完整性：溢出、丢失、取消、pending、超时及尚缺材料
有限结论：本轮能支持什么，不能支持什么
设备最终状态与清理结果
建议下一分支（仅建议，不执行）
```

astra输出四项：`VALID / PARTIAL / INVALID`、可接受的因果结论、需要补的最小证据、批准的下一试验编号。审计者要直接打开原始PNG/JSON并核对关键行，不能仅复述sol摘要。任何实际关闭期hold未证实、before无效、旧boot混入、重复启动采集器的组都不得判VALID。

最终修复验收：隔离开关全部关闭，同固件覆盖首播、0.2秒及1秒global_output、真实Stop/replay、菜单/音效/画面；至少3个独立软件boot各通过目标序列，其中至少一次用户确认画面与菜单；真正冷启动需用户配合后另计。Stop/replay若表现不同，单列问题，不能假设两种黑屏根因相同。高负载/其他编码验证排在主故障修复之后。
