5. 从路由器找新IP并SSH，完成首次用户/密码/shell初始化；`findmnt /`、`lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS`确认根在USB而非eMMC。

## USB优先启动为何生效

保留的Armbian `aml_autoscript`内容包含：

```text
setenv bootcmd 'run start_autoscript; run storeboot'
setenv start_usb_autoscript 'for usbdev in 0 1 2 3; do if fatload usb ${usbdev} 1020000 s905_autoscript; then autoscr 1020000; fi; done'
setenv upgrade_step 2
saveenv
```

其功能是保存“先找外置脚本，再走Android”的环境。之后Android root只读核对过实际`bootcmd=run start_autoscript; run storeboot`，证明外置优先入口已存在；不是凭“插盘自动启动”猜测。首次激活会改bootloader环境；后续本项目CoreELEC的普通USB启动脚本不再saveenv、不写eMMC。下一台需确认该入口已激活，不能默认出厂如此。

## CoreELEC U盘成功启动链

项目基于CoreELEC 21.3 NG/4.9.269，以该Android bootloader运行USB `s905_autoscript`，用`booti`加载原始ARM64 Image、原CE initramfs封装的uInitrd和本板DTB。通用布局：内核0x11000000、initrd 0x15000000、DTB 0x18000000。脚本同包还提供`aml_autoscript`、`cfgload`入口。

当前新机应使用构建产物中`*-E900V21C-USB-TEST.img.gz`整盘镜像，不拿普通Generic包直接替代本板镜像。手动更新必须同一构建的Image/uInitrd/DTB/SYSTEM及脚本成套，按[e900-port部署文档](../../boards/ARTIFACTS-AND-MANUAL-USB-DEPLOY.md)核对（具体文件名以产物manifest和当前脚本为准）。旧实验中的`SYSTEM291`等带编号文件是特定现场，不能泛用到新机。

拔掉U盘后回到eMMC Android是本机保留的恢复路径。当前不把CoreELEC写入eMMC，不运行`ceemmc`，也不把Armbian安装eMMC步骤混入此档案。只有Armbian有线SSH并不能证明本板eMMC/无线/HDMI在Linux均可用。
